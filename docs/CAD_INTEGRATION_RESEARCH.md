### Recommended Architecture: Dual-Engine Approach

#### **Primary Engine: build123d**

**Why build123d?**

1. **Superior Python Integration**
   - Native Python library (no CLI required)
   - Pythonic API with context managers and operators
   - Direct object manipulation and filtering
   ```python
   with BuildPart() as bracket:
       with BuildSketch():
           Rectangle(50, 30)
       extrude(amount=10)
       with BuildSketch(bracket.faces().sort_by(Axis.Z)[-1]):
           Circle(5)
       extrude(amount=-5, mode=Mode.SUBTRACT)

   bracket.part.export_step("bracket.step")
   ```

2. **OpenCASCADE Kernel**
   - Industry-standard BREP (Boundary Representation) geometry
   - Supports all professional CAD formats: STEP, IGES, STL, DXF
   - Same kernel used by FreeCAD, CadQuery, and commercial CAD systems

3. **Better Assembly Support**
   - Static joints for component positioning
   - Simple, declarative assembly: "put this part here"
   - Linear scaling with assembly complexity

4. **AI-Friendly Code Generation**
   - Clean, readable Python code (easier for LLMs to generate)
   - Algebraic modeling with operators (`+=`, `-=`, `*`)
   - Less "voodoo" than CadQuery's fluent API

5. **Professional Output Quality**
   - Generates STEP files (industry standard for parametric CAD)
   - Watertight, manufacturable geometry
   - Compatible with all professional CAD/CAM tools

**Migration Path from OpenSCAD:**
- build123d supports similar primitives (Box, Cylinder, Sphere)
- Boolean operations via operators (`+`, `-`, `&`)
- Transformations via Location and Position objects
- More powerful parametric modeling capabilities

#### **Viewer/Editor: FreeCAD**

**Why FreeCAD as complementary platform?**

1. **Open Source & Free**
   - No licensing costs
   - Full source code access for customization
   - Active community (2025 development ongoing)

2. **Excellent Python API**
   - Full automation via Python scripting
   - Can run headless (no GUI) on backend
   - Import/export all formats programmatically
   ```python
   import FreeCAD
   import Part

   # Import STEP file generated by build123d
   Part.insert("model.step", "MyDocument")
   doc = FreeCAD.getDocument("MyDocument")

   # Manipulate, analyze, or re-export
   doc.saveAs("output.FCStd")
   ```

3. **Professional Features**
   - Full parametric modeling
   - 2D drafting (Technical Drawing workbench)
   - FEM analysis, CAM toolpaths, assemblies
   - Extensive workbench ecosystem

4. **Format Flexibility**
   - STEP, IGES, STL, DXF, DWG, OBJ, 3MF
   - Native .FCStd format preserves full parametric history
   - Import/export to/from all major CAD systems

5. **Deployment Options**
   - Can run on backend Docker containers
   - Headless mode for automated processing
   - Web-based viewers available (e.g., via Three.js integration)

#### **Keep Onshape for Cloud Capabilities**

Maintain current Onshape integration for:
- Cloud-based collaboration
- Web viewing without installation
- Professional document management
- API-based automation (already implemented)

**Three-Tier Output Strategy:**
1. **build123d** → STEP file (primary output)
2. **FreeCAD** → Advanced editing/viewing (optional)
3. **Onshape** → Cloud storage/collaboration (existing)

### Alternative: CadQuery vs build123d

| Aspect | build123d | CadQuery |
|--------|-----------|----------|
| **API Style** | Context managers, operators | Fluent/chained methods |
| **Learning Curve** | Moderate | Steeper |
| **Performance** | Better for assemblies | Good for single parts |
| **Community** | Growing rapidly | Established, mature |
| **Documentation** | Excellent | Excellent |
| **AI Generation** | Easier (more Pythonic) | Harder (method chains) |

**Verdict:** build123d is preferable for AI-driven generation due to its more natural Python syntax.

### Fine-Tuning Approach: Multi-Stage Strategy

#### **Stage 1: Fine-Tune Claude 3 Haiku (Immediate - 2-4 weeks)**

**Why Haiku instead of Sonnet?**
- AWS Bedrock supports Haiku fine-tuning (GA since Nov 2024)
- Sonnet/Opus fine-tuning not yet available
- Haiku is faster and cheaper for production use
- Still highly capable for code generation

**Training Data Strategy:**

1. **Synthetic Data Generation (SPCC Format)**
   - Use CAD-Llama's approach: Structured Parametric CAD Code (SPCC)
   - Convert build123d models to Python-like pseudocode with semantic annotations
   - Create hierarchical descriptions (abstract → beginner → expert levels)

   Example SPCC format:
   ```python
   # Abstract: Create a mounting bracket with bolt holes
   # Beginner: Rectangle base with circular holes
   # Expert: 50mm x 30mm x 10mm bracket, 4x M5 bolt holes, 20mm spacing

   def create_mounting_bracket():
       """A mounting bracket for securing components"""
       with BuildPart() as bracket:
           # Create base plate (50mm x 30mm)
           with BuildSketch():
               Rectangle(50, 30, align=(Align.CENTER, Align.CENTER))
           extrude(amount=10)

           # Add mounting holes (M5, 20mm spacing)
           with BuildSketch(bracket.faces().sort_by(Axis.Z)[-1]):
               with GridLocations(20, 15, 2, 2):
                   Circle(2.5)  # M5 clearance hole
           extrude(amount=-10, mode=Mode.SUBTRACT)
   ```

2. **Dataset Sources:**

   **Option A: Fusion 360 Gallery Dataset (42,912 models)**
   - Pre-existing STEP files with segmentation
   - Convert to build123d Python code
   - Add natural language annotations via GPT-4 Vision
   - SPCC-adaptive pretraining approach

   **Option B: DeepCAD Dataset (178K models)**
   - Larger dataset with construction sequences
   - Includes sketch + extrusion history
   - Better for parametric modeling

   **Option C: Custom Dataset (Recommended for MVP)**
   - 500-1,000 manually curated examples
   - Focus on common mechanical parts: brackets, enclosures, gears, fasteners
   - High-quality annotations with engineering constraints
   - Include manufacturing notes (tolerances, materials, processes)

3. **Multi-Task Training:**
   - **Text-to-CAD**: Natural language → build123d code
   - **CAD Completion**: Partial model → complete design
   - **CAD Captioning**: Model → detailed description
   - **CAD Editing**: "Add 4 holes to this bracket" → modified code
   - **Constraint Validation**: Check if design is manufacturable

**Training Resources (Based on CAD-Llama findings):**
- SPCC pretraining: ~38 A100 GPU hours, 70M tokens
- Instruction tuning: ~12 A100 GPU hours, 6M tokens
- **Total AWS Bedrock cost estimate:** $3,000-5,000 for 1,000 model dataset

**Expected Improvements:**
- 15-30% better accuracy on CAD-specific tasks (based on CAD-Llama results)
- More precise geometric specifications
- Better handling of engineering constraints
- Faster inference (Haiku is 3-5x faster than Sonnet)

#### **Stage 2: Continued Pre-Training (Medium-term - 2-3 months)**

If Bedrock enables continued pre-training for Claude:
- Train on massive corpus of CAD documentation
- Python CAD library documentation (build123d, CadQuery, FreeCAD)
- Engineering handbooks (Machinery's Handbook, GD&T standards)
- OpenCASCADE documentation
- Manufacturing process guides

**Dataset Size:** 1-10GB of text
**Cost Estimate:** $10,000-20,000 on AWS Bedrock

#### **Stage 3: Advanced Fine-Tuning (Long-term - 6+ months)**

**Wait for Sonnet/Opus Fine-Tuning:**
- AWS Bedrock will likely enable Sonnet fine-tuning in 2025
- Apply same datasets to more powerful base model
- Expect even better results (CAD-Llama showed Llama3-8B → 63.58% accuracy, beating GPT-4)

**Multi-Modal Fine-Tuning:**
- Image-to-CAD: Upload sketch/photo → generate build123d code
- Use Claude's vision capabilities with CAD images
- Train on paired (image, STEP, code) datasets
- Leverage CAD-MLLM research (multimodal conditioning)

### Migration from OpenSCAD to build123d

**Code Generation Comparison:**

**OpenSCAD (Current):**
```scad
// Mounting bracket
difference() {
    cube([50, 30, 10], center=true);
    translate([15, 10, -5])
        cylinder(h=20, r=2.5);
    translate([-15, 10, -5])
        cylinder(h=20, r=2.5);
    translate([15, -10, -5])
        cylinder(h=20, r=2.5);
    translate([-15, -10, -5])
        cylinder(h=20, r=2.5);
}
```

**build123d (Recommended):**
```python
from build123d import *

with BuildPart() as bracket:
    # Create base
    with BuildSketch():
        Rectangle(50, 30, align=(Align.CENTER, Align.CENTER))
    extrude(amount=10)

    # Add holes with grid pattern
    with BuildSketch(bracket.faces().sort_by(Axis.Z)[-1]):
        with GridLocations(30, 20, 2, 2):
            Circle(2.5)  # M5 clearance holes
    extrude(amount=-10, mode=Mode.SUBTRACT)

# Export professional formats
bracket.part.export_step("bracket.step")
bracket.part.export_stl("bracket.stl")
bracket.part.export_dxf("bracket.dxf")
```

**Key Advantages:**
- ✅ More readable/maintainable
- ✅ Better error messages
- ✅ STEP export (parametric)
- ✅ Native Python (easier to integrate)
- ✅ Easier for LLMs to generate

## 10. Risk Analysis & Mitigation

### Technical Risks

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Fine-tuning doesn't improve quality | Medium | High | Start with prompt engineering; validate gains before investing |
| build123d learning curve for users | Medium | Medium | Keep OpenSCAD option; gradual migration |
| STEP file compatibility issues | Low | Medium | Validate with major CAD tools (SolidWorks, Fusion, FreeCAD) |
| AWS Bedrock cost overruns | Medium | Medium | Set strict budgets; monitor usage; switch to Haiku |

### Business Risks

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Competitors release better AI CAD | High | High | Move fast on Phase 1-2; build moat via custom models |
| Users prefer manual CAD | Low | High | Target specific use cases (rapid prototyping, concept design) |
| Monetization challenges | Medium | High | Freemium model; enterprise tier for fine-tuning |
| Dataset quality issues | Medium | High | Manual QA; iterative improvement; user feedback loop |

## Conclusion & Recommendation

### Recommended Path Forward

**Short-Term (1-2 months):** Phase 1 - Enhanced prompting + build123d integration
- Lowest risk, highest short-term ROI
- Validates product-market fit for STEP output
- Minimal investment ($0 infrastructure)

**Medium-Term (2-4 months):** Phase 2 - Fine-tune Claude 3 Haiku
- Contingent on Phase 1 success
- Moderate investment ($5-8K)
- 15-30% quality boost + cost reduction

**Long-Term (6-12 months):** Phase 3-4 - Full platform
- Conditional on traction and funding
- High investment ($50-200K)
- Positions for enterprise market

### Why This Approach Works

1. **Incremental Validation:** Each phase validates the next
2. **Low Initial Risk:** Phase 1 requires almost no capital
3. **Fast Iteration:** See results in weeks, not months
4. **User-Driven:** Let real feedback guide fine-tuning focus
5. **Competitive:** STEP + build123d + fine-tuned Claude = unique offering

- 50%+ improvement in user satisfaction
